# Лекция 3. Borrow checker — заимствование и его правила

> Move (лекция 2) учил «отдать значение насовсем». Но постоянно отдавать неудобно. Чаще нужно
> просто **дать посмотреть** или **дать поменять**, не теряя владение. Это и есть заимствование
> (borrowing) через ссылки `&` и `&mut`. Borrow checker — часть компилятора, которая следит, чтобы
> ссылки были безопасны. Эта лекция объясняет его правила и как с ним дружить.

---

## 1. Ссылки: `&` и `&mut`

Ссылка — это «адрес» значения, по которому можно к нему обратиться, **не забирая владение**.

```rust
let s = String::from("ворон");
let r = &s;            // r — неизменяемая ссылка на s
println!("{}", r);     // читаем через ссылку
println!("{}", s);     // ✅ s всё ещё наш — мы его не отдавали
```

Два вида ссылок:
- `&T` — **неизменяемая** (shared) ссылка: можно читать, нельзя менять. Таких может быть много одновременно.
- `&mut T` — **изменяемая** (mutable/exclusive) ссылка: можно менять. Такая может быть только **одна**.

```rust
fn add_dust(s: &mut String) {   // принимаем изменяемую ссылку
    s.push_str(" в пыли");
}
let mut name = String::from("ворон");  // переменная должна быть mut
add_dust(&mut name);                   // одолжили на изменение
println!("{}", name);                  // "ворон в пыли" — изменилось у владельца
```

## 2. Два правила заимствования (сердце borrow checker)

В каждый момент времени для одного значения можно иметь **либо одно, либо другое**, но не вместе:

> **ЛИБО** сколько угодно неизменяемых ссылок `&T` (много читателей),
> **ЛИБО** ровно одну изменяемую ссылку `&mut T` (один писатель).

Плюс третье, неявное правило:
> Ссылка не может пережить значение, на которое указывает (об этом — лекция 4 про lifetime).

Картинка:
```
✅ &T, &T, &T        — много читают, никто не пишет: безопасно
✅ &mut T            — один пишет, никто больше не смотрит: безопасно
❌ &T + &mut T       — кто-то читает, пока другой пишет: ГОНКА → запрещено
❌ &mut T + &mut T   — двое пишут одновременно: ГОНКА → запрещено
```

---

## 3. Зачем это правило (не «компилятор вредничает»)

Представь: ты читаешь список, пока другой код в него что-то дописывает. Дописывание может заставить
`Vec` перевыделить память в куче (когда кончилось место), и твоя ссылка станет указывать в никуда —
**use-after-free**, крах или порча данных. В многопоточности это ещё и **гонка данных** (data race).

Rust ловит этот класс ошибок **на этапе компиляции**, бесплатно в рантайме. Правило «один писатель
или много читателей» — ровно то, что делает гонки невозможными.

## 4. Классический пример конфликта

```rust
fn main() {
    let mut titles = vec![String::from("Свеча"), String::from("Пыль")];
    let first = &titles[0];              // ① неизменяемая ссылка внутрь Vec
    titles.push(String::from("Тень"));   // ② хотим изменить Vec — нужна &mut
    println!("{}", first);               // ③ а тут ещё пользуемся ссылкой ①
}
```

Ошибка:
```
error[E0502]: cannot borrow `titles` as mutable because it is also borrowed as immutable
  |
  |   let first = &titles[0];
  |               ------ immutable borrow occurs here
  |   titles.push(...);
  |   ^^^^^^^^^^^^^^^^ mutable borrow occurs here
  |   println!("{}", first);
  |                  ----- immutable borrow later used here
```

**Перевод:** «ты держишь ссылку `first` внутрь вектора и одновременно пытаешься вектор поменять —
`push` мог бы переселить данные, и `first` повисла бы. Запрещено.»

### Как чинить
**Способ А — использовать ссылку ДО изменения** (сократить её жизнь):
```rust
let first = &titles[0];
println!("{}", first);   // ссылка отработала здесь
titles.push(String::from("Тень"));  // теперь Vec свободен — меняем спокойно
```
**Способ Б — не держать ссылку, а скопировать нужное значение:**
```rust
let first = titles[0].clone();   // независимая копия, в Vec больше не смотрим
titles.push(String::from("Тень"));
println!("{}", first);
```

## 5. NLL — почему «ссылка живёт до последнего использования»

Современный Rust умён: ссылка считается «живой» не до конца блока `}`, а **до последнего места, где её
реально используют**. Это называется Non-Lexical Lifetimes (NLL). Поэтому способ А выше работает —
после `println!("{}", first)` ссылка `first` больше не нужна, и `push` уже не конфликтует.

```rust
let mut v = vec![1, 2, 3];
let r = &v[0];
println!("{}", r);   // r последний раз использован здесь → дальше он "мёртв"
v.push(4);           // ✅ ОК: r уже не живёт, конфликта нет
```

Вывод: часто достаточно **переставить строки** так, чтобы чтение и запись не пересекались по времени.

---

## 6. Срезы (slices) — это тоже заимствования

`&str` — это срез строки, `&[T]` — срез вектора. Срез **заимствует** кусок чужих данных, не владея ими.
Поэтому, пока жив срез, исходные данные нельзя менять — то же правило.

```rust
let s = String::from("тихий дом");
let word = &s[..5];   // срез "тихий" — заимствует часть s
// s.clear();         // ❌ нельзя, пока жив word
println!("{}", word);
```

## 7. Частый затык: менять коллекцию во время итерации

```rust
let mut v = vec![1, 2, 3];
for x in &v {        // & — итерируемся по неизменяемым ссылкам
    if *x == 2 {
        v.push(99);  // ❌ нельзя менять v, пока идёт цикл по &v
    }
}
```
**Решение:** собери изменения отдельно, примени после цикла; или используй `retain`/`iter().filter()`:
```rust
v.retain(|x| *x != 2);   // безопасное удаление по условию
```

## 8. Borrow checker в реальном коде Gotiga

Открой rate-limiter — `check_rate_limit` (`services/mod.rs:106`):
```rust
let mut map = self.general_rate_limiter.lock().await;
let entry = map.entry(key).or_default();   // ① одно заимствование map
entry.retain(|t| now.duration_since(*t) < window);
entry.push(now);
```

Наивно новичок написал бы так — и **получил бы ошибку**:
```rust
let entry = map.get(&key);          // неизменяемое заимствование map
map.insert(key, vec![now]);         // ❌ изменяемое заимствование, пока живо первое
println!("{:?}", entry);
```
Здесь два заимствования `map` пересекаются. Метод `entry()` решает проблему элегантно: он берёт **одно**
заимствование и сразу даёт изменяемый доступ к ячейке (`.or_default()` создаёт пустую, если ключа нет).
Поэтому `entry` API в Rust так любят — оно обходит конфликт «сначала прочитать, потом записать».

## 9. Лучшие практики

- По умолчанию передавай в функции `&T` (почитать) или `&mut T` (поменять и вернуть владельцу), а не забирай владение.
- Если borrow checker ругается — **не лепи `.clone()` рефлекторно**. Сначала спроси: «не могу ли я просто использовать ссылку раньше / сузить её жизнь / переставить строки?»
- Для «прочитать-или-вставить» в `HashMap` бери `.entry(...).or_default()` / `.or_insert_with(...)` — одно заимствование вместо двух.
- Не меняй коллекцию, по которой идёшь циклом. Используй `retain`, `drain`, или собирай изменения отдельно.
- `&str` в параметрах вместо `&String`, `&[T]` вместо `&Vec<T>` — гибче и идиоматичнее.

---

## 10. Шпаргалка ошибок

| Ошибка компилятора | Что значит | Лечение |
|--------------------|-----------|---------|
| `cannot borrow ... as mutable because it is also borrowed as immutable` | держишь `&` и хочешь `&mut` одновременно | использовать `&` раньше, или скопировать значение |
| `cannot borrow ... as mutable more than once` | две `&mut` сразу | оставить одну; разнести по времени |
| `cannot borrow ... as mutable` (переменная не `mut`) | забыл `mut` у владельца | `let mut x = ...` |
| `borrowed value does not live long enough` | ссылка переживает источник | см. лекцию 4 (lifetime) |
