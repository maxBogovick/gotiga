# Лекция 5. Box — указатель в кучу и трейт-объекты

> `Box<T>` — самый простой «умный указатель» в Rust. Он решает две конкретные задачи: положить данные
> в кучу (heap) и спрятать разные типы за одним трейтом. Эта лекция объясняет, что такое куча, зачем
> вообще `Box`, как он чинит рекурсивные типы и почему без него не работает `Vec<dyn Trait>`. В конце —
> разбор задач блока 5.

---

## 1. Напоминание: стек и куча

- **Стек** — быстрый, но требует знать размер значения **на этапе компиляции**. Числа, `bool`, ссылки.
- **Куча (heap)** — для данных, чей размер неизвестен заранее или которые должны жить дольше текущего вызова.

`Box<T>` — это «положи `T` в кучу, а на стеке держи только указатель на него». Указатель имеет
фиксированный размер (как адрес), поэтому всегда помещается на стек.

```
Стек             Куча
┌──────────┐     ┌─────────────┐
│ box ─────┼───► │ значение T  │
└──────────┘     └─────────────┘
```

`Box<T>` — это владеющий указатель: когда `Box` выходит из scope, и память в куче, и значение
освобождаются автоматически (всё те же правила владения из лекции 2). Никакого ручного `free`.

---

## 2. Простейшее использование

```rust
let b = Box::new(5);     // 5 лежит в куче, b — указатель на стеке
println!("{}", *b);      // * разыменовывает: достаём значение, печатаем 5
println!("{}", b);       // часто * не нужен — Box "прозрачен" для многих операций
```

Для простого `i32` так делать **не нужно** — это лишняя аллокация. `Box` оправдан в двух случаях ниже.

---

## 3. Случай 1: рекурсивные типы (бесконечный размер)

Представь связанный список или дерево шагов:
```rust
enum Step {
    Done,
    Next(Step),   // ❌ ошибка: recursive type `Step` has infinite size
}
```
Почему ошибка? Чтобы положить `Step` на стек, компилятор должен знать его размер. Но `Next` содержит
`Step`, который содержит `Step`, который... — размер получается **бесконечным**. Компилятор сдаётся:
```
error[E0072]: recursive type `Step` has infinite size
  |  recursive without indirection
help: insert some indirection (e.g., a `Box`) to break the cycle
```

Решение — `Box`. Он заменяет «вложенный `Step`» на «указатель на `Step` в куче». Указатель — фиксированного
размера, цикл размеров разрывается:
```rust
enum Step {
    Done,
    Next(Box<Step>),   // ✅ теперь размер известен: тег + указатель
}
```
```
Step = либо Done (просто тег),
       либо Next(указатель) ──► [ Step в куче ]
```

Запомни подсказку компилятора дословно: **«insert some indirection (e.g., a Box)»** — «добавь
косвенность через указатель». Box — это и есть косвенность.

## 4. Случай 2: трейт-объекты `Box<dyn Trait>`

Это мостик к лекции о трейтах (л.6) и самый практичный повод для `Box`.

Допустим, есть трейт «уведомитель» и несколько реализаций:
```rust
trait Notifier {
    fn send(&self, msg: &str);
}

struct EmailNotifier;
struct LogNotifier;

impl Notifier for EmailNotifier {
    fn send(&self, msg: &str) { println!("EMAIL: {}", msg); }
}
impl Notifier for LogNotifier {
    fn send(&self, msg: &str) { println!("LOG: {}", msg); }
}
```

Хотим хранить **разные** уведомители в одном `Vec` и звать `send` у каждого. Наивно:
```rust
let notifiers: Vec<dyn Notifier> = ...;   // ❌ doesn't have a size known at compile-time
```
Ошибка! `dyn Notifier` означает «какой-то тип, реализующий `Notifier`» — а у разных типов **разный
размер**. `Vec` не может хранить элементы неизвестного/разного размера.

Решение — `Box<dyn Notifier>`: каждый объект лежит в куче, а в `Vec` хранятся **указатели**
фиксированного размера:
```rust
let notifiers: Vec<Box<dyn Notifier>> = vec![
    Box::new(EmailNotifier),
    Box::new(LogNotifier),
];
for n in &notifiers {
    n.send("Свеча зажжена");   // вызовется правильный send для каждого типа
}
```

### Что такое `dyn` и «динамическая диспетчеризация»
`dyn Notifier` — это **трейт-объект**. Программа в рантайме хранит не только указатель на данные, но и
указатель на таблицу методов (vtable) этого конкретного типа. Когда ты зовёшь `n.send(...)`, нужный
`send` выбирается **в рантайме** по vtable. Это называется динамическая диспетчеризация — чуть
медленнее прямого вызова, но даёт гибкость хранить разные типы вместе.

## 5. Случай 3: `Box<dyn Error>` (бонус — пригодится дальше)

Когда функция может вернуть ошибки **разных** типов, удобно вернуть их за общим трейтом:
```rust
fn do_stuff() -> Result<(), Box<dyn std::error::Error>> {
    let n: i32 = "42".parse()?;       // ParseIntError
    std::fs::read_to_string("x")?;    // io::Error
    Ok(())
}
```
`Box<dyn Error>` означает «какая-то ошибка, реализующая трейт `Error`». В Gotiga для бизнес-кода вместо
этого используется свой enum `AppError` (точнее и понятнее), но `Box<dyn Error>` — стандартный приём для
прототипов и `main`.

## 6. Box vs enum — когда что

И `Box<dyn Trait>`, и enum со всеми вариантами решают «много разных типов в одном месте». Как выбрать?

| | `enum` со всеми вариантами | `Box<dyn Trait>` |
|---|---|---|
| Когда вариантов мало и они известны | ✅ лучше: явно, быстро, `match` | избыточно |
| Когда типов много / добавляются извне | громоздко | ✅ лучше: открыто для расширения |
| Скорость | быстрее (статика) | чуть медленнее (vtable) |
| Размер | по самому большому варианту | указатель |

Правило: **знаешь все варианты заранее и их немного → enum. Типов много или их добавляют плагины/чужой
код → `Box<dyn Trait>`.**

## 7. Box и владение

`Box<T>` подчиняется тем же правилам владения (л.2): он **владеет** содержимым, его можно move, при выходе
из scope он чистит кучу. То есть `Box` — это не «сборщик мусора», а обычное владение, просто данные в куче.

```rust
let a = Box::new(String::from("ворон"));
let b = a;             // Box переехал (move), a больше не валиден
// println!("{}", a);  // ❌ moved
println!("{}", b);     // ✅
```

---

## 8. Лучшие практики

- Не оборачивай в `Box` без причины. `Box::new(5)` для обычного числа — лишняя аллокация.
- Три легитимных повода для `Box`: (1) рекурсивный тип, (2) трейт-объект `Box<dyn Trait>` в коллекции/возврате, (3) очень большой объект, который дорого двигать по стеку.
- Для разнородных коллекций: `Vec<Box<dyn Trait>>`. Помни — нужен `dyn` и `Box`, потому что у `Vec` элементы должны быть одного известного размера.
- Если вариантов мало и они фиксированы — предпочти `enum`, а не `Box<dyn Trait>`.
- В рантайм-критичном коде помни про стоимость динамической диспетчеризации (vtable) — но не оптимизируй преждевременно.

---

## 9. Шпаргалка ошибок

| Ошибка | Значение | Лечение |
|--------|----------|---------|
| `recursive type has infinite size` | enum/struct содержит сам себя напрямую | обернуть вложенное поле в `Box` |
| `doesn't have a size known at compile-time` | пытаешься хранить `dyn Trait` или `str` по значению | обернуть в `Box` (или использовать ссылку `&dyn`) |
| `the trait ... cannot be made into an object` | трейт не «object-safe» (есть дженерик-методы и т.п.) | убрать дженерики из методов трейта, либо не использовать `dyn` |
