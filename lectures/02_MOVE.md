# Лекция 2. Move — владение и «куда уехало моё значение»

> Эта лекция объясняет, почему в Rust значение может «уехать» из переменной и она перестаёт
> работать. Ты поймёшь, что такое владение (ownership), move, `Copy`, и научишься выбирать между
> move, `&` (заимствованием) и `.clone()`. В конце — разбор задач из блока 2.

---

## 1. Зачем Rust вообще это придумал

В большинстве языков память чистит либо программист руками (C/C++ — легко выстрелить себе в ногу),
либо сборщик мусора (Java/Go/Python — удобно, но тормозит и непредсказуемо).

Rust выбрал третий путь: **владение** (ownership). Компилятор на этапе сборки точно знает, кто
отвечает за каждый кусок памяти и когда его освобождать. Никакого сборщика мусора, и при этом
невозможно случайно освободить память дважды или обратиться к уже освобождённой.

Move — это и есть механизм, который делает это правило железным. Поняв move, ты понял половину Rust.

---

## 2. Три правила владения (выучить наизусть)

1. У каждого значения есть ровно **один владелец** (переменная).
2. Владелец может быть только **один** в каждый момент.
3. Когда владелец выходит из области видимости (`}`), значение **освобождается** (drop).

```rust
{
    let s = String::from("ворон"); // s — владелец строки
    // ... s можно пользоваться ...
} // здесь s вышел из scope → строка освобождена автоматически
```

Тебе не надо звать `free` — компилятор сам вставит освобождение в конце scope. Бесплатно и безопасно.

---

## 3. Стек и куча — где что лежит

Чтобы понять move, надо знать, где живут данные.

- **Стек** — быстрый, маленький, для значений известного фиксированного размера: `i32`, `bool`, `char`, ссылки.
- **Куча (heap)** — для данных, чей размер заранее неизвестен или меняется: содержимое `String`, `Vec`.

`String` устроен хитро. Сама переменная на стеке — это маленькая «обёртка» из трёх полей:
```
Стек (переменная s)            Куча (сами байты)
┌───────────────┐              ┌───┬───┬───┬───┬───┐
│ ptr  ─────────┼────────────► │ в │ о │ р │ о │ н │
│ len = 5       │              └───┴───┴───┴───┴───┘
│ cap = 5       │
└───────────────┘
```
`ptr` — указатель на байты в куче, `len` — длина, `cap` — сколько выделено. Запомни эту картинку — move станет очевидным.

---

## 4. Что такое move

Когда ты присваиваешь `String` другой переменной или передаёшь в функцию — Rust **копирует обёртку
со стека** (ptr/len/cap), но **НЕ** копирует байты в куче (это было бы дорого).

```rust
let a = String::from("ворон");
let b = a;   // обёртка скопирована: теперь a и b показывают на одни байты
```

И вот проблема: если бы и `a`, и `b` считались владельцами одних байтов, то в конце scope
освобождение случилось бы **дважды** (double free) — классическая ошибка C++. Rust это запрещает так:
после `let b = a;` переменная `a` **становится недействительной** (moved). Владение «уехало» в `b`.

```rust
let a = String::from("ворон");
let b = a;
println!("{}", a); // ❌ ОШИБКА: borrow of moved value: `a`
```

Текст ошибки компилятора:
```
error[E0382]: borrow of moved value: `a`
  |
  |   let b = a;
  |           - value moved here
  |   println!("{}", a);
  |                  ^ value borrowed here after move
```

**Перевод на человеческий:** «ты отдал значение в `b`, у `a` больше ничего нет, нельзя им пользоваться».

---

## 5. Почему `i32` не «уезжает», а `String` уезжает — трейт `Copy`

```rust
let x = 5;
let y = x;
println!("{}", x); // ✅ работает! x всё ещё валиден
```

Числа, `bool`, `char` целиком лежат на стеке, копировать их **дёшево и безопасно** (нет указателей в
кучу, нечего освобождать дважды). Такие типы реализуют трейт `Copy` — при присваивании они
**копируются**, а не «уезжают».

Правило:
- Тип `Copy` (числа, `bool`, `char`, кортежи из `Copy`) → при присваивании **копируется**, оригинал жив.
- Тип не-`Copy` (`String`, `Vec`, твои структуры со `String`) → при присваивании **move**, оригинал мёртв.

> Запомни короткую формулу: «маленькое и без кучи — `Copy`; большое или с кучей — move».

## 6. Move при вызове функции

Передача аргумента работает так же, как присваивание:

```rust
fn make_label(s: String) -> String {
    format!("Экспонат: {}", s)
}

fn main() {
    let name = String::from("Ворон");
    let label = make_label(name); // name УЕХАЛ в функцию
    println!("{}", name);         // ❌ ошибка: name больше не наш
}
```

Функция `make_label` **забрала владение** `name`. После вызова `name` использовать нельзя.

---

## 7. Три способа починить — и как выбрать

### Способ А — заимствование `&` (чаще всего ПРАВИЛЬНЫЙ)
Дай функции **посмотреть** на строку, не забирая её:
```rust
fn make_label(s: &str) -> String {        // принимаем ссылку
    format!("Экспонат: {}", s)
}
fn main() {
    let name = String::from("Ворон");
    let label = make_label(&name);        // одолжили, не отдали
    println!("{} / {}", name, label);     // ✅ name всё ещё наш
}
```
Это самый дешёвый вариант: ничего не копируется, никто не теряет владение. Подробно про `&` — в лекции 3.

### Способ Б — `.clone()` (когда правда нужна вторая независимая копия)
```rust
let label = make_label(name.clone()); // отдали копию, оригинал цел
println!("{}", name);                 // ✅
```
`.clone()` копирует **и байты в куче тоже** — это реальная стоимость. Используй, только когда тебе
действительно нужны **две независимые** строки. `.clone()` «чтобы заткнуть компилятор» — частая ошибка новичка.

### Способ В — вернуть владение обратно
```rust
fn make_label(s: String) -> (String, String) {
    let label = format!("Экспонат: {}", s);
    (s, label) // возвращаем строку вызывающему
}
```
Громоздко, применяется редко. Знать стоит, выбирать — почти никогда.

### Как выбрать (правило большого пальца)
```
Функции нужно только ПОСМОТРЕТЬ значение? → бери &T (способ А)  ← по умолчанию
Функции нужно ИЗМЕНИТЬ, но вернуть владельцу? → &mut T (лекция 3)
Нужны ДВЕ независимые копии?              → .clone() (способ Б)
Значение тебе больше не нужно?            → отдай move, это нормально
```

В 80% случаев правильный ответ — **`&` (заимствование)**. `.clone()` — только осознанно.

## 8. Частичный move (partial move)

Можно «увести» одно поле структуры, и тогда вся структура частично инвалидируется:
```rust
struct Order { name: String, email: String }

let order = Order { name: "Аня".into(), email: "a@b.c".into() };
let n = order.name;          // увели поле name
println!("{}", order.email); // ✅ email ещё на месте
println!("{:?}", order.name);// ❌ name уехал
```
Поэтому в реальном коде поля обычно **заимствуют** (`&order.email`), а не уводят.

## 9. Move в реальном коде Gotiga

Открой `create_order` (`handlers.rs`):
```rust
pub async fn create_order(
    State(service): State<AppService>,
    headers: HeaderMap,
    Json(order): Json<OrderRequest>,   // ← тело запроса въехало во владение хендлера
) -> Result<Json<OrderCreatedResponse>> {
    // ...
    let saved = service.create_order(&order, user_id).await?;  // ← &order: одолжили, не отдали
    // ...
}
```
Обрати внимание: `Json(order)` забрал владение телом запроса (move из сети в переменную), а в сервис
оно передаётся как **`&order`** — потому что сервису надо только прочитать заказ, а не присвоить его себе.
Если бы передали `order` (move), переменная стала бы недоступна для остального кода хендлера.

Это и есть практический смысл move: ты постоянно решаешь «отдать насовсем или дать посмотреть».

---

## 10. Лучшие практики

- По умолчанию принимай в функции **`&T` / `&str`**, а не `T` / `String`. Забирай владение, только если оно тебе правда нужно (например, кладёшь значение в структуру/БД надолго).
- `.clone()` — это видимая стоимость. Прежде чем писать `.clone()`, спроси: «мне правда нужна вторая копия, или я просто борюсь с компилятором?» Если второе — нужно `&`.
- `&str` лучше `&String` в параметрах: принимает и `String`, и строковый литерал.
- Не борись с move «копированием всего подряд» — это медленно и выдаёт новичка.
