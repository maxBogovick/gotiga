# Локальный индекс по смыслу: тексты и фото

Что здесь: программа, которая берёт ваши работы, байки, вестник и карты, считает
по ним векторы (эмбеддинги) и позволяет искать словами, вопросами и картинкой.
Работает на этом компьютере, ничего никуда не отправляет (после первой загрузки
весов моделей). Сайт эту папку не использует: это инструмент для опытов и основа,
если потом понадобится ответ с поиском по текстам.

## Запуск

```
python3 -m venv .venv-tools/embed
.venv-tools/embed/bin/pip install -r tools/embed/requirements.txt

.venv-tools/embed/bin/python tools/embed/build.py          # собрать индекс (≈4 мин, 91 работа, 12 байок, 1154 фото)
.venv-tools/embed/bin/python tools/embed/search.py --serve # страница http://127.0.0.1:8765
.venv-tools/embed/bin/python tools/embed/search.py "ведьма с метлой"
.venv-tools/embed/bin/python tools/embed/search.py "снежная зима" --photos
.venv-tools/embed/bin/python tools/embed/search.py --like ~/Downloads/foto.jpg
```

`build.py` читает публичные ручки (GET) локального сервера; `--base
https://ritunia.com/api/v1` берёт данные с прода. Повторный запуск считает
вектора только для изменённых кусков и новых фото (по хешу текста и адреса).

## Что внутри

- **Текст:** `BAAI/bge-m3` (многоязычная, читает до 8192 знаков; здесь 512).
  Работы, байки и карты режутся на куски по ~900 знаков (`common.py`), каждый
  язык — отдельные куски; вещь находится по лучшему из кусков, поэтому запрос по-русски
  находит английский текст.
- **Фото:** SigLIP 2 `so400m-patch14-384` (≈4 ГБ весов, 1154 фото считаются за
  3,5 мин на M5) — общее пространство картинок и подписей, понимает запросы на
  нескольких языках. Лёгкая `google/siglip2-base-patch16-224` через
  `--image-model` в 1,5 раза хуже (таблица ниже).
- Поиск — перебор по всем векторам в numpy: на тысячах кусков это
  миллисекунды, отдельная база векторов не нужна. Понадобится при десятках тысяч.
- Индекс лежит в `index/` (не в git).

## Замер текстовой модели

`eval_text.py` прогоняет 129 фраз из `tools/search/cases.json` (снимок
`tools/search/corpus.json`), верные вещи отмечены там же. Разработчик писал
фразы сам, поэтому число показывает «не стало ли хуже», а не качество на живых
запросах; одна фраза — 0,8 пункта.

| модель | первая верная | в первых трёх | в первых шести |
|---|---|---|---|
| multilingual-e5-small (как на сервере) | 94,6 % | 97,7 % | 98,4 % |
| BAAI/bge-m3 | 88,4 % | 98,4 % | 99,2 % |

e5-small точнее на первой позиции, bge-m3 лучше находит «по смыслу» («привидение»)
и держит длинные тексты, но в 3 раза тяжелее и медленнее (75 с против 31 с на тех
же кусках). Для опытов взята bge-m3; `--text-model intfloat/multilingual-e5-small`
даёт лёгкий вариант.

## Замер поиска фото

`eval_photos.py`: запрос — название работы (без слов «кукла», «small», «doll»),
верно, если среди первых фото есть фото этой работы. Берутся работы с названием,
которого нет у других. Метка слабая (название описывает не всё, что видно на
фото), поэтому число годится для сравнения моделей.

| модель | язык | первое фото верно | в первых 5 | в первых 10 |
|---|---|---|---|---|
| siglip2-base | ru | 41,1 % | 61,6 % | 69,9 % |
| siglip2-base | en | 53,2 % | 71,4 % | 81,8 % |
| siglip2-so400m | ru | 60,3 % | 76,7 % | 82,2 % |
| siglip2-so400m | en | 61,0 % | 75,3 % | 85,7 % |
| siglip2-so400m | de | 64,8 % | 77,5 % | 87,3 % |
