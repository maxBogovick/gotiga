# Замер поиска по всему сайту

Что здесь: чем проверяется, что поиск в шапке находит нужное, и как перемерить
после любой правки ранжирования.

- `fetch_corpus.py` — снимает с публичных ручек (только GET) то, что ищет поиск:
  работы, небылицы, листы вестника, карты → `corpus.json`.
- `cases.json` — 135 фраз: имена на шести языках, те же вещи «другими словами»,
  вопросы, опечатки и 6 фраз, на которые ничего находиться не должно. У каждой —
  номера верных вещей (первые 8 знаков). **Фразы писал не посетитель, а
  разработчик**: число показывает, не стало ли хуже, но не обещает, что так
  будет на живых запросах. Настоящие неудачные запросы стоит дописывать сюда.
- `../../src-tauri/server/examples/search_probe.rs` — прогон на сервере: вектор
  (multilingual-e5), слова, триграммы, бонус за слова в названии.

```
python3 tools/search/fetch_corpus.py                 # обновить снимок
cd src-tauri/server
EMBED_WEIGHTS_DIR=/путь/к/весам \
  cargo run --release --example search_probe -- -v --name 0.01 --any 0.01 --common 0.25
... -- --sweep                                        # перебор бонусов
```

Веса (≈490 МБ: `model.safetensors`, `tokenizer.json`, `config.json`) берутся с
`huggingface.co/intfloat/multilingual-e5-small`; на машине автора их нет, в
сборке сервера их кладёт `Dockerfile`.

Бонус подбирается на чётных фразах и проверяется на нечётных (подбор их не
видел), как у каталога ответов (`tools/ask/`).

## Что замерено (22.10.2026, 129 фраз с верным ответом)

| | прежний поиск | новый |
|---|---|---|
| верная вещь первая | 89,9 % | 90,7 % |
| в первых трёх | 93,0 % | 96,9 % |
| в первых шести | 95,3 % | 98,4 % |
| вопросы, в первых трёх | 53 % | 100 % |
| «dragon», «Bitcoin», «футбол» | 6 результатов | пусто |

Прежний поиск воспроизведён в браузере настоящим кодом (`searchSite`), но
смысловую часть его (порядок работ от `/search`) пришлось взять из этой же
пробы, потому что локальный сервер в отладочной сборке считает запрос около
15 секунд. На живом сервере порядок хуже (пример: «where is gnomes with weapon»
давал ведьму первой), так что разрыв в пользу нового больше, чем в таблице.

Порог на каждую вещь (`--floor 0.02`): ответ сокращается с 32 до 11 вещей в
среднем, верная остаётся, кроме одной фразы («дровосек», стоял третьим с оценкой
0,0159). Порог 0,03 даёт 6 вещей и на этих фразах не хуже, но метрика ищет
первую верную вещь, а не все подходящие, поэтому для широких запросов («witch»:
15 работ) порог в 0,03 не проверен; взят более мягкий 0,02.

Снимок данных берётся с полными текстами небылиц: со срезанными замер не видел
неточных совпадений слов, которые видит сервер (так «dragon» находил небылицу,
пока бонус «слово в любом поле» принимал опечатки; теперь он точный). Остаётся
ложная находка у «pizza recipe» (кухонный стол бабушки): одна из 6 фраз «ничего».

Без весов модели (`--no-vector`, так сейчас работает локальный сервер на машине
автора): первая верная вещь 86,0 % (подбор 92,3 / проверка 79,7), в первых
трёх 94,6 %; порог 0,02 сокращает ответ с 17 до 7 вещей.

Что не находится: «привидение» (модель не связывает со «Little ghost»), «дровосек»
стоит третьим. Бонус по названию: 0,01–0,05 на подборе дают одно и то же,
взято наименьшее.
